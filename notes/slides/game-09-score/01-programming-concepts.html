Game 09 — Score

Programming concepts

Feature branches

Until now, every commit went straight onto main. That's fine while building the first working version. Once the game works, it's worth protecting: a half-finished feature shouldn't break it.

So each feature gets its own branch:

git switch -c score       # start a branch for the feature
# ... write code, test, commit (as many commits as needed) ...
git switch main           # back to the working game
git merge score           # bring the finished feature in
git branch -d score       # tidy up

While you work on the branch, main still has the last working version. If the feature goes badly, you can abandon the branch, and main is untouched.

Changing what a function returns

handleCollisions() used to do its work and return nothing. Now it also returns the points scored:

score += handleCollisions(bullets, aliens);

+= adds the returned value to score. A frame with no hits returns 0, so the score doesn't change. The function still doesn't touch score itself, which keeps it easy to test: the tests check the number it returns.

Changing a function's parameters

createAlienGrid() gained a fourth parameter, pointsList. Every place that calls the function must now pass it, and that includes the tests. A missing argument isn't an error in JavaScript: the parameter is just undefined, and the program fails later, somewhere else (see "How I developed this").

Lists that line up with rows

const ALIEN_ROW_POINTS = [30, 20, 20, 10];   // points for each row, top row first

The same idea as the row colours in stage 5: a list with one entry per row, read with pointsList[row % pointsList.length]. A const array at the top of the file makes the scoring easy to find and change.

Text alignment

textAlign(RIGHT, TOP);
text("SCORE " + score, width - 10, 10);

textAlign(RIGHT, TOP) makes the given position the text's top-right corner. As the score grows from 0 to 640, the text grows to the left and never runs off the edge of the canvas.
