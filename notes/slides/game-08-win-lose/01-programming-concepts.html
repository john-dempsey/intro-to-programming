Programming concepts

Game states

The game is always in exactly one of three states: playing, won or lost. One variable records which:

let gameState;            // STATE_PLAYING, STATE_WON or STATE_LOST

Different parts of the program check it to decide what to do. draw() only moves things while playing, and keyPressed() only fires while playing and only restarts when the game is over.

It can help to draw the states as boxes, with arrows for what moves the game from one to another:

FromToWhen
playingwonno aliens left
playinglostan alien reaches the ship
won or lostplayingthe player presses Enter

Constants for the states

const STATE_PLAYING = "playing";
const STATE_WON = "won";
const STATE_LOST = "lost";

The states could just be typed as strings everywhere: gameState === "won". But if you mistype a string ("Won", "wonn"), JavaScript doesn't complain. The comparison is simply never true, and the game silently misbehaves. Mistype a constant's name (STATE_WONN) and you get an error naming the problem. Constants turn silent bugs into loud ones.

Separating "update" from "draw"

if (gameState === STATE_PLAYING) {
    updateGame();     // move things, check collisions, check win/lose
}
drawGame();           // draw everything where it is now

Up to stage 7, functions like updateBullets() moved and drew in the same loop. To freeze the game while still showing it, moving and drawing have to be separate, so one can happen without the other. Most games are organised this way: an update step, then a draw step, every frame.

One function to start a game

resetGame() sets every part of the game to its starting value. setup() calls it once, and pressing Enter calls it again. Because both use the same function, a new game is guaranteed to start exactly like the first one. If the start-up code were written twice, sooner or later someone would change one copy and forget the other.

!==

gameState !== STATE_PLAYING means "is not equal to": true when the game is won or lost. It's the opposite of ===.

Transparency again

fill(0, 0, 0, 160);
rect(0, 0, width, height);

The fourth value in fill() is alpha, from section 00. A see-through black panel over the whole canvas darkens the frozen game, so the message stands out but the player can still see how the game ended.
