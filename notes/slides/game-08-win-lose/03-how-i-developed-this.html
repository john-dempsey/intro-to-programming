Game 08 — Winning and Losing

How I developed this

Attempt 1: wrap draw() in an if

My first idea was to put everything in draw() inside if (gameState === STATE_PLAYING). When I lost, the game stopped, but the screen went blank behind the message: the drawing code was inside the if too, so nothing was drawn. The player couldn't see how they'd lost.

The problem was that moving and drawing were mixed together in the same functions. So before going any further, I refactored: split updateBullets() into moving and displaying, and split draw() into updateGame() and drawGame(). I committed the refactor on its own, after checking the game still played exactly the same and all the tests passed. Then the freeze was a one-line if.

Testing it without playing for 40 seconds

Losing takes about 40 seconds of not firing, and winning means shooting 32 aliens. Testing every change that way would have taken all day. Instead, I used the console to set up the situation I wanted:

aliens.splice(1)            // leave one alien, then shoot it to test winning
aliens[0].moveBy(0, 400)    // send an alien past the ship to test losing

It's the same idea as the automatic tests: put the program into a known state, then check what it does.

The bullets that wouldn't move

After winning, I pressed space out of habit. A bullet appeared at the cannon and stayed there, frozen. keyPressed() still fired, but updateGame() wasn't running to move anything. Firing should only happen while playing, so I added && gameState === STATE_PLAYING. It's easy to miss this kind of bug: every new state is a new situation for every part of the program, and each part needs checking.

A silent typo

At first I typed the state names as strings. In one place I wrote "Won" instead of "won". When I won, the game froze with no message. No error, no failing test. It took a breakpoint in draw() and a close look at the gameState value to spot the capital letter. I replaced every string with a constant, so a typo now causes an error that names the problem.

Decision: where is "too low"?

The game is lost when an alien reaches the top of the ship, not the bottom of the screen. If the aliens could reach the bottom, they'd have to pass through the ship first, which would look wrong. Using ship.getBounds() means this still works if the ship's size or position changes.

Manual checks

  • Shoot every alien: "YOU WIN!" appears, and the game freezes behind it.
  • Let the aliens reach the ship: "GAME OVER" appears at the moment an alien touches the ship.
  • After either, arrow keys and space do nothing.
  • Enter during a game does nothing; Enter after a game starts a fresh one, with 32 aliens moving right and no bullets.
  • D works in every state, and shows the current state.
  • The console shows only PASS lines.
