Reading the sketch

setup() and resetGame()

function setup() {
    createCanvas(CANVAS_WIDTH, CANVAS_HEIGHT);

    resetGame();
    runTests();
}

function resetGame() {
    ship = new Ship(width / 2, height - SHIP_MARGIN, SHIP_WIDTH, SHIP_HEIGHT, SHIP_SPEED, color(0, 220, 120));
    bullets = [];

    let rowColours = [color(255, 80, 80), color(255, 180, 0), color(80, 200, 255), color(200, 120, 255)];
    aliens = createAlienGrid(ALIEN_ROWS, ALIEN_COLUMNS, rowColours);
    alienDirection = 1;

    gameState = STATE_PLAYING;
}

Everything that used to be set up in setup() or at the top of the file now happens in resetGame(). The global variables are still declared at the top, but without starting values; a comment says where they get them.

draw()

function draw() {
    background(BACKGROUND_COLOUR);

    if (gameState === STATE_PLAYING) {
        updateGame();
    }

    drawGame();

    if (gameState === STATE_WON) {
        displayMessage("YOU WIN!", "Press Enter to play again");
    } else if (gameState === STATE_LOST) {
        displayMessage("GAME OVER", "Press Enter to play again");
    }

    if (showDebug) {
        displayDebugInfo();
    }
}

Read it top to bottom: update (only while playing), draw (always), then a message on top if the game is over, then the debug overlay on top of everything.

Update and draw

function updateGame() {
    ship.move(readDirection());
    alienDirection = marchAliens(aliens, alienDirection);
    moveBullets();
    handleCollisions(bullets, aliens);
    gameState = checkGameState(aliens, ship.getBounds().top);
}

function drawGame() {
    ship.display();
    displayAliens();
    displayBullets();
}

updateBullets() from earlier stages has been split into moveBullets() and displayBullets(). The last line of updateGame() works out whether this frame ended the game.

Won, lost or still playing?

function checkGameState(alienList, shipTop) {
    if (alienList.length === 0) {
        return STATE_WON;
    }

    for (let i = 0; i < alienList.length; i++) {
        if (alienList[i].getBounds().bottom >= shipTop) {
            return STATE_LOST;
        }
    }

    return STATE_PLAYING;
}

The same "is any alien...?" search as formationAtEdge() in stage 6, with an early return. Like marchAliens(), it doesn't change gameState itself; it returns the answer and the caller stores it, so the tests can call it with any list of aliens.

if (key === " " && gameState === STATE_PLAYING) {

p5's keyCode and its ENTER constant identify the Enter key. The debug overlay works in every state.

To prove resetGame() resets things, the test first puts every part of the game into a "wrong" state. If it only checked a fresh game, it couldn't tell whether resetGame() changed anything at all.
