Game 02 — Moving the Ship

How I developed this

Attempt 1: keyPressed()

My first version used keyPressed(), as in Frogger. It worked, but the ship moved one step per key press, so crossing the screen took dozens of presses. Frogger moves in steps; Space Invaders needs smooth movement. I switched to keyIsDown().

I tried this on a Git branch so I could throw it away easily. Exercise 6 has you do the same.

Attempt 2: keyIsDown() inside move()

Next, I wrote move() to check the keys itself:

move() {
    if (keyIsDown(LEFT_ARROW)) {
        this.x -= this.speed;
    }
    // ...
}

The ship moved nicely, but when I came to write the tests I couldn't: the only way to make the ship move was to press a key. So I refactored (changed how the code is organised without changing what it does): readDirection() reads the keys, and move(direction) does the moving. The game behaved exactly the same, but now move() could be tested.

The bug the tests caught

I wrote the edge tests before the clamp, expecting the ship's centre to stop 25 pixels from each edge. Then I wrote a quick clamp:

if (this.x < 0) {
    this.x = 0;
}

It looked right when I ran the game, until I noticed half the ship disappeared off the edge. The console agreed:

FAIL: stops at the left edge (expected 25, got 22)

I was clamping the ship's centre, not its edge. Sketch 13 had already solved this with the radius; for the ship, it's half its width. After the fix, every test passed.

Manual checks

  • Hold left until the ship stops: it's fully visible, touching the edge.
  • The same on the right.
  • Hold both arrow keys: the ship stays still.
  • Press no keys: the ship stays still.
  • Tap quickly: the ship moves a small amount each time.
  • The console shows only PASS lines.
