Programming concepts

keyIsDown() versus keyPressed()

p5 gives two ways to react to the keyboard:

keyPressed()keyIsDown(key)
What it isA function you write; p5 calls itA function p5 provides; you call it
When it runsOnce, at the moment a key goes downWhenever you call it; returns true while the key is held
Good forOne action per press: firing, pausingSmooth, continuous movement

Calling keyIsDown() inside draw() checks the key 60 times a second, so the ship keeps moving for as long as the key is held.

A direction as a number

this.x += direction * this.speed;

direction is -1 (left), 0 (still) or 1 (right). Multiplying by it gives -speed, 0 or +speed, so one line handles all three cases without an if. This is the same idea as the sign of vx in sketch 11.

Separating input from logic

If move() called keyIsDown() itself, the only way to test it would be to press keys. Instead, the work is split in two:

  • readDirection() reads the keyboard and returns a direction. It's short and simple enough to check by hand.
  • move(direction) does the actual work. A test can call move(1) directly, with no keyboard involved.

Keeping code that talks to the outside world (keyboard, mouse, screen) separate from code that does calculations is one of the most useful habits in programming. It makes the calculations easy to test and easy to reuse.

Independent tests

function makeTestShip(startX) {
    return new Ship(startX, 200, 50, 20, 5, color(255));
}

Each check gets a brand-new ship from makeTestShip(). If the tests shared one ship, a move in one test would change the starting point of the next, and a failure in one could cause false failures in the others. Tests should not depend on each other.

Testing edge cases

An edge case is an unusual input that might break the code, like the ball wider than the canvas in sketch 13. Here, the edge cases are the canvas edges themselves: a ship 2 pixels from the edge, and a ship moved 1000 times in a row. Normal cases (moving in the middle of the screen) rarely find bugs; edge cases often do.
