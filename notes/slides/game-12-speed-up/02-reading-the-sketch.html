Reading the sketch

Two speeds instead of one

const ALIEN_START_SPEED = 1;  // pixels per frame, sideways, with every alien alive
const ALIEN_TOP_SPEED = 4;    // pixels per frame, sideways, with one alien left

ALIEN_SPEED is gone. These two constants describe the slowest and fastest the formation can go.

Working out the speed

function alienSpeedFor(aliensLeft) {
    let fullGrid = ALIEN_ROWS * ALIEN_COLUMNS;
    return map(aliensLeft, fullGrid, 1, ALIEN_START_SPEED, ALIEN_TOP_SPEED);
}

A full grid gives the start speed, one alien gives the top speed. fullGrid is worked out from the grid's size rather than written as 32, so the function still works if the grid changes.

It's given the number of aliens rather than looking at the aliens array itself, so a test can ask "how fast with 8 aliens?" without building 8 aliens.

Using it every frame

alienDirection = marchAliens(aliens, alienDirection, alienSpeedFor(aliens.length));

This line in updateGame() works the speed out again every frame. There's no "current speed" variable that has to be updated whenever an alien is destroyed: the speed always matches the number of aliens, because it's calculated from it.

        let nextX = alienList[i].x + direction * speed;

Stage 6's formationAtEdge() checks where each alien is about to be. A faster alien's next step is bigger, so the check has to know the speed as well. If it still assumed a step of 1, a fast formation would overshoot the edge before turning.

The debug overlay

text("alien speed: " + alienSpeedFor(aliens.length).toFixed(2), 10, 120);

toFixed(2) turns a number into text with exactly two decimal places, so the overlay shows 2.55 rather than 2.5483870967741935.

The tests

testAlienSpeed() checks both ends of the range, that fewer aliens means faster, and one value in the middle, using checkClose() because it's a decimal.

The stage 6 march tests now pass a speed of 1, written out as a number. If they used ALIEN_START_SPEED, tuning the game would change what the tests check. The tests are about marching and turning, not about how fast the game should feel.
