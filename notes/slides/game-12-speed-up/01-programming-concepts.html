Programming concepts

One range to another: map()

The speed should depend on how many aliens are left: 1 pixel per frame with all 32, rising steadily to 4 pixels per frame with just one. That's a question of turning a number in one range (32 down to 1) into a number in another range (1 up to 4). p5's map() does exactly that:

map(value, start1, stop1, start2, stop2)

When value is start1, you get start2. When it's stop1, you get stop2. In between, you get the number the same fraction of the way along. Read the five values in pairs: start1 goes with start2, and stop1 goes with stop2.

Aliens leftSpeed (pixels per frame)
321.00
241.77
162.55
83.32
14.00

map() doesn't stop at the ends of the range: give it a value outside the first range and you get one outside the second. Exercise 5 asks whether that matters here.

A constant becomes a parameter

Until now, marchAliens() used the constant ALIEN_SPEED. A constant can't change while the game runs, so the speed is now a parameter:

function marchAliens(alienList, direction, speed) {

marchAliens() doesn't know or care where the speed comes from. The game passes in alienSpeedFor(aliens.length); the tests pass in 1. This is the same idea as stage 2's move(direction): a function that is given what it needs is easier to reuse and easier to test than one that reaches out for it.

Decimals aren't exact

Type this into the console:

0.1 + 0.2           // 0.30000000000000004
0.1 + 0.2 === 0.3   // false

Computers store most decimal numbers as very close approximations, not exactly. Usually you'd never notice, but === notices: two calculations that should give the same answer can differ in the last few decimal places. So the tests have a new helper for decimals, checkClose(), which passes if the answer is close enough:

function checkClose(description, actual, expected, tolerance) {
    if (abs(actual - expected) <= tolerance) {
        console.log("PASS: " + description);
    } else {
        console.error("FAIL: " + description + " (expected " + expected + " +/- " + tolerance + ", got " + actual + ")");
    }
}

abs() gives the size of a number without its sign, so abs(actual - expected) is how far apart the two numbers are, whichever is bigger. The tolerance is how far apart they're allowed to be. Use check() for whole numbers, text and booleans, and checkClose() for decimals that come out of a calculation.

Numbers you tune by playing

Nobody can work out the "right" top speed on paper. It has to be tried, and changed, and tried again, ideally by someone who isn't the programmer. Because the two speeds are constants at the top of the sketch, tuning them is a one-line change that can't break anything else.
