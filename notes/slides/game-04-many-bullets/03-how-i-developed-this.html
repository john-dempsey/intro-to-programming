Game 04 — Many Bullets

How I developed this

Changing the plan

The original game allows one bullet at a time, and that's what the plan said. After playing stage 3 for a few minutes, it felt slow. I decided to allow many bullets instead. Plans are meant to change as you learn more. I updated the plan to match, so it stayed accurate: see src/game/04-many-bullets/PLAN.md, which now has a "Changes to the plan" section.

Attempt 1: no removal

The first version just pushed bullets into the array and moved them. It looked perfect. But I knew bullets that left the screen were still in the array, so I added the debug overlay to see how many there were:

bullets in array: 143

The number only ever went up. Every bullet ever fired was still being moved, every frame, somewhere far above the screen. In a long game that would slowly use more memory and slow the game down. Nothing on screen showed the problem; only the overlay did.

Attempt 2: removing while looping forwards

I added removal to the existing loop, going forwards as usual:

for (let i = 0; i < bulletList.length; i++) {
    if (bulletList[i].isOffScreen()) {
        bulletList.splice(i, 1);
    }
}

I played for a while with the overlay on, and the count went back to 0 every time. It seemed to work. Then I wrote the tests, including one with three off-screen bullets:

FAIL: removes every bullet that is off screen (expected 0, got 1)

I traced the loop on paper (the table on the concepts page) and saw the skipped item. In the game, the skipped bullet was just removed one frame later, so I could never have seen it by playing. But in a later stage, when a bullet and an alien are removed in the same frame, a skipped item could mean an alien that should be destroyed isn't. That would be much harder to track down then.

This is the main reason for automatic tests: they find bugs you can't see.

Attempt 3: loop backwards

Looping backwards fixed it, and all the tests passed. I also moved the removal into its own function, removeOffScreenBullets(), which takes the array as a parameter. That made it possible to test with small arrays built just for the tests.

Manual checks

  • Press space quickly several times: several bullets in flight at once.
  • With the overlay on, the count goes up with each shot and back to 0 when they've all gone.
  • Hold space: one bullet per press, not a stream.
  • Press D twice: the overlay turns on, then off.
  • The frame rate stays at about 60 while firing quickly.
  • The console shows only PASS lines.
