Programming concepts

null: "nothing here"

let bullet = null;   // null means "no bullet on screen"

null is a special value meaning "no object". The variable bullet holds either a Bullet or null, and the code checks which before using it:

if (bullet !== null) {
    bullet.move();
}

The check matters. Calling a method on null, such as bullet.move() when there's no bullet, is an error: Cannot read properties of null. It's one of the most common errors in JavaScript, so it's worth recognising.

Two kinds of keyboard input together

Stage 2's table showed keyIsDown() suits continuous movement and keyPressed() suits one action per press. This stage uses both: arrow keys with keyIsDown(), and space with keyPressed().

function keyPressed() {
    if (key === " ") {
        fireBullet();
    }
}

Inside keyPressed(), p5's key variable holds the key that was pressed, as a string. A space is " ".

A method that answers a question

isOffScreen() {
    return this.y + this.bulletHeight / 2 < 0;
}

A comparison like a < b produces true or false (a boolean, from sketch 13). return sends that value back to whoever called the method, so bullet.isOffScreen() can go straight into an if. Methods that answer yes/no questions are often named isSomething or hasSomething, so the if reads almost like English: if (bullet.isOffScreen()).

Values are copied at the moment they're used

bullet = new Bullet(ship.x, startY, ...);

The bullet's x is set to ship.x at the moment of firing. The number is copied into the bullet; it isn't linked to the ship. That's why moving the ship afterwards doesn't move the bullet.

The console can run code

The browser console doesn't just show messages. You can type JavaScript into it while the sketch is running, such as ship.x or bullet, and see the current value straight away. It's often the quickest way to answer "what is this variable right now?"
