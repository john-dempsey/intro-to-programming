Game 03 — Firing a Bullet

Reading the sketch

Changes to Ship

constructor(x, y, bodyWidth, bodyHeight, speed, shipColour) {
    // ...
    this.cannonWidth = bodyWidth / 5;
    this.cannonHeight = bodyHeight / 2;
}

// The y position of the top of the cannon, where bullets come from.
cannonTopY() {
    return this.y - this.bodyHeight / 2 - this.cannonHeight;
}

The cannon's size used to be worked out inside display(). Now cannonTopY() needs it too, so it's worked out once, in the constructor, and stored as a property. The top of the cannon is the ship's centre, minus half the body, minus the cannon.

The Bullet class

move() {
    this.y -= this.speed;    // up the screen, so y gets smaller
}

isOffScreen() {
    return this.y + this.bulletHeight / 2 < 0;    // bottom edge past the top
}

A bullet only goes up, so it needs a single speed rather than vx and vy. It's off screen once its bottom edge has passed the top, so the whole bullet has gone, not just half of it.

Firing

function fireBullet() {
    // Only fire if there isn't already a bullet on screen.
    if (bullet === null) {
        let startY = ship.cannonTopY() - BULLET_HEIGHT / 2;
        bullet = new Bullet(ship.x, startY, BULLET_WIDTH, BULLET_HEIGHT, BULLET_SPEED, color(255));
    }
}

The new bullet's bottom edge sits exactly on top of the cannon. If a bullet already exists, nothing happens.

Each frame

function updateBullet() {
    if (bullet !== null) {
        bullet.move();

        if (bullet.isOffScreen()) {
            bullet = null;   // gone, so the player can fire again
        } else {
            bullet.display();
        }
    }
}

Setting bullet back to null is what allows the next shot: it makes the check in fireBullet() true again.

The new tests

function testOnlyOneBullet() {
    bullet = null;
    fireBullet();
    check("firing creates a bullet", bullet !== null, true);

    let firstBullet = bullet;
    fireBullet();
    check("firing again while a bullet is on screen does nothing", bullet, firstBullet);

    bullet = null;
}

This test uses the game's real bullet variable, so it cleans up after itself by setting it back to null. Otherwise the game would start with a bullet already on screen. The second check compares objects: === on two objects is true only if they're the very same object, which proves no new bullet was made.

testBulletOffScreen() checks the exact boundary: a 12-pixel bullet at y = -6 is just touching the top (on screen), and at y = -7 it's gone. Bugs often hide at boundaries like this.
