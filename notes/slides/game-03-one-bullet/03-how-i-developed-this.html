How I developed this

Attempt 1: firing with keyIsDown()

I already had keyIsDown() working for the arrow keys, so I used it for space as well, in draw():

if (keyIsDown(32)) {   // 32 is the key code for space
    fireBullet();
}

At that point fireBullet() didn't check for an existing bullet. Holding space, the bullet seemed stuck just above the ship. To see what was happening, I added one line to fireBullet():

console.log("fire at frame " + frameCount);

The console filled up with a new line every frame. A brand-new bullet was replacing the old one 60 times a second, each starting at the cannon. Firing is a once-per-press action, so I moved it into keyPressed() and deleted the console.log() line.

A console.log() added to find a bug should always be removed once the bug is fixed. Left in, they clutter the console and hide the messages that matter.

Refactoring the cannon

To start the bullet at the cannon, I needed the cannon's height outside display(). I could have copied the calculation, but then changing the cannon's shape would mean changing it in two places, and sooner or later I'd forget one. So I moved it to the constructor and added cannonTopY(). I ran the tests and checked the ship still looked the same before going on: a refactor shouldn't change what the program does.

The bug: one shot only

My next version fired perfectly, once. After that, space did nothing. No errors, no failing tests. I typed bullet into the console:

Bullet {x: 320, y: -2417, ...}

Typing it again gave an even bigger negative number. The bullet had left the screen long ago but still existed, moving upwards forever, so fireBullet() thought there was still a bullet on screen. I'd written isOffScreen() but never used it. Adding the check in updateBullet() fixed it, and I added testOnlyOneBullet() to make sure the "one at a time" rule stays correct.

Manual checks

  • Press space: one bullet leaves the top of the cannon and travels straight up.
  • Move while the bullet is in flight: the bullet keeps going straight.
  • Press space again while a bullet is on screen: nothing happens.
  • Once the bullet has gone, space fires again.
  • Hold space down: only one bullet is fired.
  • Fire from each edge of the screen.
  • The console shows only PASS lines.

The commits

The refactor got its own commit, before the new feature. If the feature had gone wrong, I could have gone back to the refactored version without losing it.
