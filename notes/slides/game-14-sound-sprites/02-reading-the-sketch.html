Reading the sketch

One more library

<script src="../../libraries/p5.min.js"></script>
<script src="../../libraries/p5.sound.min.js"></script>

Sound isn't part of p5 itself. p5.sound is an extra library, loaded in index.html straight after p5, which adds loadSound(), userStartAudio() and the play() method.

Loading the sprites

function preload() {
    loadSprite("squid", "assets/alien-squid.png");
    loadSprite("crab", "assets/alien-crab.png");
    loadSprite("octopus", "assets/alien-octopus.png");
    loadSprite("ship", "assets/ship.png");
}

loadSprite() calls loadImage() with the two callbacks from the concepts page: one adds the image to sprites, the other prints a warning.

Loading the sounds

function setup() {
    createCanvas(CANVAS_WIDTH, CANVAS_HEIGHT);
    noSmooth();   // keep the pixel-art edges sharp when sprites are resized
    loadSounds();

The sounds are loaded from setup(), not preload(), so p5 doesn't wait for them. The game starts straight away and each sound is added to sounds when it arrives. A sound file that's slow, or missing, can never hold up the start.

noSmooth() matters because the sprites are drawn smaller than their files (the crab file is 44 × 32 pixels, drawn at 30 × 20). Normally p5 blends neighbouring pixels when resizing, which makes pixel art look blurred.

Drawing an alien

display() {
    let sprite = sprites[spriteNameForPoints(this.points)];
    if (sprite) {
        push();
        imageMode(CENTER);
        tint(this.col);
        image(sprite, this.x, this.y, this.alienWidth, this.alienHeight);
        pop();
    } else {
        this.displayShapes();
    }
}
  • spriteNameForPoints() turns an alien's points into a name: 30 is a squid, 20 a crab, 10 an octopus.
  • imageMode(CENTER) works like rectMode(CENTER): the image is centred on x and y.
  • The sprite files are white. tint() colours an image the way fill() colours a shape, so each row keeps its own colour, and one file serves both crab rows.
  • The old drawing code moved, unchanged, into displayShapes().

Playing the sounds

let pointsScored = handleCollisions(bullets, aliens);
if (pointsScored > 0) {
    playSound(sounds.explosion);
}
score += pointsScored;

handleCollisions() returns 0 when nothing was hit, so points mean an explosion. fireBullet() ends with playSound(sounds.shoot), and losing a life plays sounds.playerHit. If a sound hasn't loaded, sounds.explosion is undefined, and playSound() skips it.

The keys

function keyPressed() {
    // Browsers don't allow a page to play sound until the user has
    // pressed a key or clicked. This tells p5 the user has done that.
    userStartAudio();

Further down, M flips soundOn with !, just as D does for the debug overlay. When sound is off, the score panel says SOUND OFF.

The new tests

function makeFakeSound() {
    return {
        timesPlayed: 0,
        play: function () {
            this.timesPlayed += 1;
        }
    };
}
  • testPlaySound() plays a fake with sound on, then off, then plays undefined to check that a missing sound doesn't cause an error.
  • testFiringPlaysSound() swaps the real shoot sound for a fake, fires, checks the fake was played once, and puts the real sound back.
  • testDrawingWithoutSprites() empties sprites and draws a ship and an alien, to prove the shapes still work.

Tests that swap something real for a fake always put the real one back at the end, so the game isn't affected.
