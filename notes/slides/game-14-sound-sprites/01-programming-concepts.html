Programming concepts

Loading files: preload()

An image file takes time to arrive, even from your own computer. If draw() tried to use it before then, there'd be nothing to draw. p5 has a third special function for this:

  • preload() runs first. Start loading files here.
  • p5 waits until every file started in preload() has loaded, or failed.
  • Only then does it call setup(), and then draw() over and over.

Callbacks: "call this when you're done"

loadImage() can be given two extra values, and both are functions:

loadImage(filePath,
    function (loadedImage) {
        sprites[name] = loadedImage;
    },
    function () {
        console.warn("Couldn't load " + filePath + ", so shapes will be drawn instead");
    });

Neither function runs straight away. p5 keeps them, and calls the first when the file has loaded, or the second if it can't be loaded. A function passed in to be called later like this is called a callback. These two have no names, because nothing else ever needs to call them.

You've used this idea since sketch 02: you write draw(), but p5 decides when to call it.

Looking things up by name

let sprites = {};

sprites starts as an empty object. Each image is added under a name as it loads: sprites["crab"] = loadedImage. Square brackets let the name be a variable; sprites.ship means the same as sprites["ship"].

Ask for a name that was never added and you get undefined. In an if, undefined counts as false, so this is how the game asks "did this sprite load?":

if (sprites.ship) {
    // draw the image
} else {
    // draw the shapes from stage 1
}

Carry on without it

If a file can't be loaded, the game could stop with an error, or it could do the next best thing. Here the next best thing is easy: draw the shapes the game used before, or play no sound. Doing the next best thing instead of failing completely is called graceful degradation. It's the same question as stage 11's try/catch: if this fails, what's the most sensible thing to do?

Browsers and sound

Browsers don't let a web page play sound until the person using it has clicked or pressed a key on that page. Without this rule, any page could start making noise the moment it opened. p5's userStartAudio() tells the browser that the player has now done something, so sound can start. The game calls it on every key press, before anything else.

Every sound through one function

function playSound(sound) {
    if (soundOn && sound) {
        sound.play();
    }
}

Every sound in the game is played by calling playSound(), never .play() directly. So the M key's setting, and the check that the sound actually loaded, are written once, in one place. A new sound added later can't forget either check.

Testing without hearing

A test can't listen. Instead, the tests swap in a fake: a plain object that has a play() method, like a real sound, but only counts how many times it was called. playSound() can't tell the difference, so the test can check the count.
