Programming concepts

Event-driven vs. continuous execution

Every sketch so far has done everything either once (setup()) or on a fixed schedule (draw(), ~60 times a second) — the program runs on its own timetable, whether or not anything happens in the outside world. This sketch introduces a different way for code to run: event-driven execution, where a block of code runs only in response to something happening — here, a mouse click or a key press — rather than on any schedule. This is a general idea, not specific to p5 or even to graphics: buttons, forms, and just about every interactive program are built around code that waits and reacts to events instead of running start-to-finish. p5 gives this idea a concrete form via event callback functions, covered below.
