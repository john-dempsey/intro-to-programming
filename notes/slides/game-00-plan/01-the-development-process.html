Game 00 — The Plan

The development process

Small steps, always working

It's tempting to write the whole game in one go, then run it. When it doesn't work (and it won't), you have hundreds of new lines and no idea which one is wrong.

Instead, the game is built in stages. Each stage adds one small feature, and the game must run at the end of every stage. If something breaks, the problem is almost certainly in the few lines you just added.

The loop for each stage

  1. Decide the one feature this stage adds. Check it's small enough to finish in one sitting.
  2. Write the code for it.
  3. Run and test it: run the automatic tests, then try it by hand.
  4. Fix anything that's wrong, using the console and the debugger.
  5. Commit it to Git, so you can always get back to this working version.

Then start the loop again with the next feature. Professional developers work this way too, usually with even smaller steps.

Why plan first?

A plan doesn't need to be long, and it will change as you go. Its job is to answer three questions before you write any code:

  • What's the smallest version that's worth having? Build that first.
  • What order should the features be built in? Some depend on others: you can't shoot aliens until you have bullets.
  • Where are the hard parts? Knowing early means they don't surprise you later.
