Game 00 — The Plan

The plan

Open PLAN.md alongside this page. Here's why each part is there.

One sentence

If you can't describe your project in one sentence, it's probably too big, or you're not yet sure what it is.

Must, should, could

Every feature goes into one of three groups:

GroupMeaningExample
Must haveWithout it, it isn't the game at allAliens march down the screen
Should haveImportant, but the game works without itScore on screen
Could haveNice extras, only if there's timeSound effects

Be strict about "must have". The fewer features in that group, the sooner you have something that works.

The smallest playable game

The "must have" features, together, are the first target. Everything after that improves a game that already works. If you run out of time, you still have a game.

Stages

The features are put in order, one per stage. The early stages are tiny on purpose: stage 1 only draws the ship. Small early stages build up a working base quickly.

Done means done

A stage isn't finished when the code is written. It's finished when it runs with no console errors, the tests pass, it's been tried by hand, and it's committed. Deciding this in advance stops "nearly done" stages piling up.

Questions I don't know the answer to yet

The plan lists the parts I wasn't sure how to do. That isn't a weakness in the plan. It shows where to spend time looking things up, and which stages may take longer.

The empty sketch

Stage 0's sketch.js is just a blank canvas. It's still worth running: it proves the HTML, the p5 library and the sketch file are all connected before any game code exists.

const CANVAS_WIDTH = 640;
const CANVAS_HEIGHT = 480;
const BACKGROUND_COLOUR = 20;   // near-black, like the original arcade game

function setup() {
    createCanvas(CANVAS_WIDTH, CANVAS_HEIGHT);
}

function draw() {
    background(BACKGROUND_COLOUR);
}
