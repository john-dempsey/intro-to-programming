Reading the sketch

The ShieldBlock class

class ShieldBlock {
    // x and y are the centre of the block.
    constructor(x, y, size, blockColour) {
        this.x = x;
        this.y = y;
        this.size = size;
        this.col = blockColour;
    }

    // The rectangle around the block, for collisions.
    getBounds() {
        return {
            left: this.x - this.size / 2,
            right: this.x + this.size / 2,
            top: this.y - this.size / 2,
            bottom: this.y + this.size / 2
        };
    }

A block is about the simplest class in the game: a square that can draw itself and report its rectangle. Its getBounds() returns an object with the same four properties as an alien's, which is what lets the collision code treat them the same way.

Building one shield

for (let row = 0; row < SHIELD_ROWS; row++) {

The same nested loop as the alien grid in stage 5, with blocks packed edge to edge: each one is exactly SHIELD_BLOCK_SIZE from the last.

Building all four

for (let shield = 0; shield < shieldCount; shield++) {
    let centreX = width * (shield + 1) / (shieldCount + 1);
    let blocks = createShield(centreX, SHIELD_TOP, blockColour);
    for (let i = 0; i < blocks.length; i++) {
        allBlocks.push(blocks[i]);
    }
}

createShield() returns one shield's blocks in an array. The inner loop copies them one by one into allBlocks, so the result is one long array of all 96 blocks (4 shields × 4 rows × 6 columns).

The collisions, each frame

// Shields stop bullets from both sides.
collideBulletsWith(bullets, shieldBlocks);
collideBulletsWith(alienBullets, shieldBlocks);

score += handleCollisions(bullets, aliens);

The return values of the two shield lines aren't used: all that matters is that the bullets and blocks are removed.

The general collision function

function collideBulletsWith(bulletList, targetList) {
    let targetsHit = [];

    for (let bulletIndex = bulletList.length - 1; bulletIndex >= 0; bulletIndex--) {
        let bulletBounds = bulletList[bulletIndex].getBounds();

        for (let targetIndex = 0; targetIndex < targetList.length; targetIndex++) {
            if (boundsOverlap(bulletBounds, targetList[targetIndex].getBounds())) {
                targetsHit.push(targetList[targetIndex]);
                bulletList.splice(bulletIndex, 1);
                targetList.splice(targetIndex, 1);
                break;   // this bullet is gone: stop checking it against other targets
            }
        }
    }

    return targetsHit;
}

Compare it with stage 7's handleCollisions(): the loops, the backwards outer loop, the two splice()s and the break are all the same. "Alien" has become "target", and instead of adding points, it remembers which targets were hit.

The target is added to targetsHit before it's spliced out of targetList. After the splice, targetList[targetIndex] would be a different target.

handleCollisions(), rebuilt

function handleCollisions(bulletList, alienList) {
    let aliensHit = collideBulletsWith(bulletList, alienList);
    return totalPoints(aliensHit);
}

The same name, parameters and result as before, so nothing that calls it had to change. totalPoints() is a plain loop that adds up the points of each alien in a list.

The new tests

  • testShieldSize(): one shield has the right number of blocks, and is centred.
  • testShieldsFitTheGap(): the shields sit below the aliens' starting position and above the ship.
  • testCollideReturnsTargetsHit(): a miss returns an empty array; a hit returns the target that was hit, and removes it.
  • testBulletsHitShields(): bullets from both directions destroy a block and are used up.
  • testTotalPoints(): including an empty list, which should give 0.

testResetGame() also checks that a new game rebuilds every shield.
