How I developed this

Refactor first

git switch -c shields

Before drawing a single shield, I changed the collision code into collideBulletsWith() and rebuilt handleCollisions() on top of it. The game should behave exactly as before, so I didn't add any tests yet: the old ones were the check.

One wrong word

I renamed alienIndex to targetIndex by hand, line by line. One test failed:

FAIL: first survivor is the left alien (expected 100, got 300)

That's testRightAlienRemoved(), from stage 7: three aliens in a row, one bullet on the middle one. The right number of aliens was removed, but the wrong one. In the game, shooting an alien in the middle of the grid made one disappear from the top-left corner.

The test's name told me where to look: whichever alien gets removed. There are two splice()s, and I'd written bulletIndex in the second:

targetList.splice(bulletIndex, 1);   // should be targetIndex

Both variables are numbers, and both are valid indexes, so JavaScript has no way to know it's wrong. This is the stage's bug hunt. When a function has two arrays and two index variables, check that each index is only ever used with its own array.

Once every test passed, I committed the refactor on its own, before starting on the shields.

Where to put the shields

Before choosing SHIELD_TOP, I wrote testShieldsFitTheGap(): the shields must start below the lowest row of aliens and end above the ship. Then I tried values until the test passed and the gap looked right. The test also protects that gap later: if someone moves the aliens or the ship, it will say so.

Is 96 blocks too many?

Every frame, every bullet is now checked against up to 96 blocks. I wasn't sure whether that would slow the game down, so rather than guess, I fired as fast as I could and watched the frame rate in the debug overlay. It stayed at 60. I also added the blocks' hitboxes to the overlay, which showed that the blocks fit together with no gaps a bullet could slip through.

Manual checks

  • Four shields, evenly spaced, between the aliens and the ship.
  • A player bullet that hits a shield removes one block and disappears.
  • So does an alien bullet.
  • Repeated shots wear a hole right through a shield.
  • Shooting an alien still destroys the alien that was hit, and scores its points.
  • A new game has four complete shields.
  • The console shows only PASS lines.

The commits

git commit -am "Refactor: collideBulletsWith() for any targets"
git commit -am "Shields made of blocks"
git commit -am "Bullets from both sides wear the shields away"
git commit -am "Show shield hitboxes in the debug overlay"
git switch main
git merge shields
git branch -d shields

The refactor and its fix were one commit: the bug never reached a commit, because I ran the tests before committing.
