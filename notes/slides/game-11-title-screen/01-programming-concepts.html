Programming concepts

Four states

FromToWhen

Enter now does different things in different states, so it has its own function, handleEnter(). Each row of the table with "Enter" in it is one branch of that function, and one check in testEnterChangesState().

if / else if versus two ifs

if (gameState === STATE_WON || gameState === STATE_LOST) {
    gameState = STATE_TITLE;
} else if (gameState === STATE_TITLE) {
    resetGame();
}

The first branch changes gameState to the very value the second branch checks for. With else if, only one branch runs, so the title screen appears. With two separate ifs, both would run one after the other: the title screen would be skipped and a new game would start straight away. Compare readDirection() in stage 2, where two separate ifs were exactly what was needed, because both keys had to be checked.

Saving data: localStorage

Variables disappear when the page is closed. localStorage is storage the browser keeps for each website, even after it's closed:

localStorage.setItem("spaceInvadersHighScore", 640);       // save
let saved = localStorage.getItem("spaceInvadersHighScore");  // load: "640", or null

Two things to know:

  • It stores text. Save 640 and you get back the string "640". Number(saved) turns it back into a number. If the text isn't a number, Number() gives NaN, which Number.isNaN() can check for.
  • getItem() returns null if nothing has been saved under that name yet, as on the very first visit.

Error handling: try / catch

You met try/catch in stage 1, protecting the tests. Here it protects the game from something outside its control: some browsers, or settings, don't allow localStorage, and using it causes an error. Without catch, that error would stop the game at the moment it tried to save the high score.

try {
    localStorage.setItem(storageKey, scoreToSave);
} catch (error) {
    console.warn("Couldn't save the high score: " + error.message);
}

Good error handling asks: if this fails, what's the most sensible thing to do? Here: carry on playing without saving, and leave a message in the console for the developer. console.warn() prints in yellow, for problems that aren't serious enough to be red errors.

Code that runs once when a state changes

endGame() must run exactly once per game, not every frame. Because updateGame() only runs while playing, checking "has the state just stopped being playing?" at the end of updateGame() can only be true once.
