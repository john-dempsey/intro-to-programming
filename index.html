Programming with p5.js

A sketch-by-sketch tutorial

This tutorial is the companion to the p5.js sketches used in lectures. It follows the same "objects early" approach as the module: you'll read working code before writing your own, and each sketch introduces a small number of new ideas on top of the last one.

Work through the sketches in order — each one builds on the ideas introduced by the sketches before it. Every sketch has its own set of pages: an overview of what the sketch is for, the programming concepts it introduces, how p5.js is using those concepts, a walkthrough of the actual code, and then tasks to try — both small modifications to the sketch itself and the two longer running projects (House and Cars → Frogger) that grow alongside the numbered sketches. Use the Next button at the bottom of each page to move through the whole tutorial in order, or jump straight to any page from the sidebar, or to a sketch from the contents below.

Contents

  1. 00 — Getting Started: How Computer Graphics Work

    How screens actually draw pictures — pixels, the canvas, coordinates, shapes, drawing modes, and colour models — before a single line of p5 code appears.

  2. 01 — Drawing a Circle

    A single circle, drawn once with hard-coded numbers — the simplest possible p5 sketch, and the starting point for everything that follows.

  3. 02 — Circle Follows the Mouse

    The same circle, now redrawn every frame inside draw() at the current mouseX/mouseY, so it appears to follow the mouse continuously.

  4. 03 — Click to Draw

    A circle stamped wherever the user clicks, with a key press clearing the canvas — the first sketch driven by mousePressed() and keyPressed() instead of just draw().

  5. 04 — Global Variables

    Sketch 03's click-to-draw redone with every hard-coded number replaced by a named global const, making the code easier to read and change.

  6. 05 — A Colour Object

    The four separate colour numbers replaced by one p5 color() object — the first object to appear in the series.

  7. 06 — A Ball Object

    A ball's position, size and colour bundled into one hand-written object literal, read and written with dot notation.

  8. 07 — A createBall() Function

    Ball construction moved into a createBall() function that takes arguments and returns a new ball object — the first function built as a reusable 'factory'.

  9. 08 — A displayBall() Function

    Ball drawing moved into a displayBall() function that takes a ball object as a parameter — the first function written to operate on data passed into it.

  10. 09 — A Ball Class

    createBall() and displayBall() merged into a single Ball class, with a constructor and a display() method — the first use of class, this and new.

  11. 10 — An Array of Balls

    Five balls at once, held in an array and displayed with a for loop — the first sketch to manage more than one object together.

  12. 11 — Ball Velocity

    Balls that move on their own every frame, each with its own velocity and a move() method — the first sketch where anything animates by itself.

  13. 12 — Wrapping Around the Edges

    Moving balls that wrap around the canvas edges like Pac-Man, using the modulo % operator instead of plain addition.

  14. 13 — Ball Bounce

    Moving balls that bounce off the canvas edges instead of wrapping, using if/else if branching to detect and react to a collision.

Developing a game

A worked example of developing a program in stages, from a plan to a finished Space Invaders game. Each stage shows how it was developed, then has exercises on planning, testing, debugging and Git to practise for your own project.

  1. Game 00 — The Plan

    The development process, a plan for the game (features, the smallest playable version, stages), and commits as save points.

  2. Game 01 — Drawing the Ship

    A Ship class drawn at the bottom of the canvas, plus the first automatic tests and the browser debugger.

  3. Game 02 — Moving the Ship

    Arrow-key movement with keyIsDown(), clamped to the canvas; separating input from logic so movement can be tested, conditional breakpoints and Git branches.

  4. Game 03 — Firing a Bullet

    One bullet at a time, fired with space; null for "nothing there", using the console to inspect the running game, the Call Stack, and staging commits with git add.

  5. Game 04 — Many Bullets

    Bullets added to and removed from an array while the game runs; why removal loops backwards, a debug overlay, and a bug only the tests can find.

  6. Game 05 — A Grid of Aliens

    An Alien class and a grid built with a nested loop, stored in one array; reading error messages, debugging inside a nested loop, and the Git history of one file.

  7. Game 06 — The Alien March

    The formation marches, drops and reverses as a group; looking ahead at an edge, an early return from a loop, regression tests, logpoints and git revert.

  8. Game 07 — Collisions

    Bullets destroy aliens: getBounds() returning an object, rectangle overlap, removing from two arrays with break, hitboxes in the debug overlay, and git commit --amend.

  9. Game 08 — Winning and Losing

    The smallest playable game: game states, constants instead of strings, separating update from draw, resetGame(), using the console to set up test situations, and tagging a milestone.

  10. Game 09 — Score

    Points by row and a score on screen; feature branches and merging, changing a function's parameters and return value, and a bug the tests didn't catch.

  11. Game 10 — The Aliens Fire Back

    Random alien fire and three lives; bullets with a velocity, testing and debugging random code with randomSeed(), and resolving a merge conflict.

  12. Game 11 — Title Screen and High Score

    A title screen and a saved high score; four game states, localStorage with try/catch, looking at old versions in Git, and git bisect.

  13. Game 12 — The Aliens Speed Up

    The aliens march faster as their numbers fall; map(), a constant that becomes a parameter, why decimals can't be compared with ===, playtesting, and git blame.

  14. Game 13 — Shields

    Shields that wear away; one collision function for any kind of target, refactoring with the tests as a safety net, and committing part of a file.

  15. Game 14 — Sound and Sprites

    Pixel-art sprites and sound effects; loading files in preload(), callbacks, carrying on when a file is missing, testing with a fake, and .gitignore.

  16. Game 15 — The Mystery UFO

    A UFO at random times; measuring time with millis(), passing the time in so it can be tested, a retrospective, a changelog, and releasing version 1.0.
